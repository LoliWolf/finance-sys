# 剩余部分 PRD

## 背景

当前 MVP 已覆盖“上传可解析文档、提取纯文本、调用 AI 抽取结构化荐股意图、用确定性规则生成候选计划、查询结果”的窄链路。

下一阶段目标是把候选计划扩展为可长期跟踪的“博主荐股表现评估系统”：系统持续跟踪所有被推荐股票，基于 Tushare 行情计算不同博主、不同股票、不同时间窗口下的胜率和盈利率。

## 目标

1. 将 AI 抽取结果沉淀为标准推荐事件，表达“博主/来源在某时间推荐某股票及方向”。
2. 接入 Tushare 获取 A 股基础信息、交易日历、日线行情、复权因子等数据。
3. 对每条推荐事件生成可复现的跟踪结果，包括收益率、是否命中止盈/止损、最大浮盈、最大回撤。
4. 按博主、股票、方向、时间区间聚合统计胜率、平均收益率、累计收益率、样本数。
5. 提供 API 支持前端或运营查询推荐明细、跟踪结果和聚合排行榜。

## 非目标

1. 不做真实自动交易、下单、风控审批。
2. 不把 AI 作为收益率或价格生成来源。
3. 不引入实时分钟级行情，第一阶段只使用日线。
4. 不做复杂因子模型、组合优化、归因分析。
5. 不恢复 Redis、MinIO、worker/scheduler 旧设计，除非后续重新确认运行边界。

## 用户角色

- 研究运营：上传文档、校对推荐事件、查看博主表现。
- 量化/策略分析：查看不同窗口收益、胜率、样本分布。
- 系统管理员：配置 Tushare token、任务窗口、评估规则。

## 业务对象

- 博主：推荐来源主体，可来自文档 `author`、AI 抽取 `analyst` 或人工补录。
- 推荐事件：一次“谁推荐了哪只股票”的事实记录。
- 行情快照：Tushare 拉取的股票基础信息、交易日历、日线行情。
- 跟踪结果：单条推荐事件在指定持有窗口内的表现。
- 统计结果：按维度聚合后的胜率和盈利率。

## 推荐事件规则

推荐事件从 `CandidatePlan` 派生，必须包含：

- `blogger_name`
- `source_document_id`
- `plan_id`
- `symbol`
- `direction`
- `recommend_date`
- `reference_price`
- `confidence`
- `thesis`
- `evidence`

去重建议：

- 同一博主、同一股票、同一方向、同一交易日来自同一文档，只保留一条主事件。
- 同一博主同日多次推荐同一股票，可保留多条原始证据，但聚合统计默认按一条事件计算。

## 行情数据需求

第一阶段使用 Tushare：

- 股票基础信息：代码、名称、市场、上市状态。
- 交易日历：判断推荐日后的 T+1、T+5、T+20 等交易窗口。
- 日线行情：开盘、最高、最低、收盘、成交量。
- 复权数据：用于收益率计算，默认使用前复权口径。

## 跟踪窗口

默认计算以下窗口：

- T+1
- T+5
- T+10
- T+20

每个窗口输出：

- 入场价：默认 T+1 开盘价；如缺失则标记为不可评估。
- 退出价：窗口最后一个交易日收盘价。
- 收益率：多头为 `(exit - entry) / entry`，空头为 `(entry - exit) / entry`。
- 是否盈利：收益率大于 0。
- 是否命中止盈/止损：使用窗口内最高/最低价与计划止盈/止损比较。
- 最大浮盈和最大回撤。

## 统计指标

按博主、股票、方向、时间区间聚合：

- 推荐次数
- 可评估次数
- 胜率
- 平均收益率
- 中位数收益率
- 累计收益率
- 最大单笔盈利
- 最大单笔亏损
- 止盈命中率
- 止损命中率

统计口径要求：

- 只统计状态为可评估的推荐事件。
- 行情缺失、停牌、代码无法识别的事件单独计数，不混入胜率分母。
- 同一事件在不同窗口下分别统计，不混用。

## API 需求

推荐事件：

- `GET /api/v1/recommendations`
- `GET /api/v1/recommendations/{id}`
- `POST /api/v1/recommendations/{id}/refresh-evaluation`

行情任务：

- `POST /api/v1/admin/market/sync-calendar`
- `POST /api/v1/admin/market/sync-daily`
- `GET /api/v1/admin/market/sync-runs`

统计查询：

- `GET /api/v1/stats/bloggers`
- `GET /api/v1/stats/bloggers/{id}`
- `GET /api/v1/stats/symbols`
- `GET /api/v1/stats/recommendations`

常用筛选参数：

- `from`
- `to`
- `blogger`
- `symbol`
- `direction`
- `window`
- `min_samples`

## 验收标准

1. 上传样本文档后，可以生成候选计划，并派生推荐事件。
2. 配置 Tushare token 后，可以同步指定日期区间的交易日历和日线行情。
3. 对一条推荐事件，可以计算 T+1、T+5、T+10、T+20 的收益率和胜负。
4. 可以查询某博主在指定区间内的推荐次数、胜率、平均收益率。
5. 同一批输入重复运行，推荐事件、行情数据、评估结果保持幂等。
6. 行情缺失时系统返回明确状态，不伪造收益结果。

## 里程碑

### M1：推荐事件沉淀

- 从 `trade_candidate_plans` 派生 `recommendation_events`。
- 建立博主实体与来源归一化。
- 提供推荐事件查询 API。

### M2：Tushare 行情接入

- 增加 Tushare 配置。
- 同步股票基础信息、交易日历、日线行情。
- 记录同步任务状态。

### M3：单条推荐评估

- 根据行情计算各窗口收益率。
- 记录不可评估原因。
- 支持手动刷新评估。

### M4：聚合统计

- 按博主、股票、方向、窗口聚合统计。
- 提供排行榜和明细查询 API。
- 增加统计结果测试数据与回归测试。
